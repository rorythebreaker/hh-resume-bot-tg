# Полное техническое задание на HH Resume Bot

Цель — получить законченный Telegram-бот для автоматизации поиска вакансий и откликов на HH.ru, основанный на `hh-applicant-tool 2.5.4`, без устаревших компонентов, дублирующего кода и незавершённых функций.

Ниже — полный перечень требований, включая первоначальные задачи, необходимые доработки и критерии готовности.

## 1. Обновление ядра

- Использовать `hh-applicant-tool 2.5.4`.
- Перейти на Python 3.12.
- Адаптировать все вызовы CLI к новой версии.
- Удалить устаревшие Playwright-патчи, если их функциональность уже реализована в ядре.
- Удалить дублирующие функции, сохранив возможности Telegram-бота.
- Обеспечить совместимость `run-apply.py`, `auth_helper.py`, `tg_bot.py` и `tg_watcher.py`.
- Проверить корректную работу всех команд после обновления.

## 2. Авторизация и профили HH.ru

- Поддерживать авторизацию через актуальный механизм HH Applicant Tool.
- Корректно работать с `token.json` и `config.toml`.
- Реализовать миграцию старых конфигураций.
- Поддерживать несколько аккаунтов HH.ru.
- Позволять переключать аккаунты через Telegram.
- Проверять действительность токена.
- Обновлять токен при истечении срока действия.
- Уведомлять о необходимости повторной авторизации.
- Не раскрывать токены, пароли и API-ключи в логах.

## 3. Автоматические отклики

- Искать вакансии по заданным параметрам.
- Выбирать резюме для откликов.
- Фильтровать вакансии по ключевым словам, региону, зарплате, опыту и формату работы.
- Исключать нежелательные вакансии и работодателей.
- Исключать уже обработанные вакансии.
- Поддерживать сопроводительные письма.
- Использовать AI для анализа вакансий и формирования писем.
- Ограничивать количество откликов.
- Поддерживать запуск по расписанию.
- Позволять запускать и останавливать обработку через Telegram.
- Формировать отчёт об успешных, пропущенных и неудачных откликах.

## 4. Ручные отклики через Telegram

- Принимать ссылки вида `https://hh.ru/vacancy/139159350`.
- Корректно извлекать ID вакансии.
- Получать сведения о вакансии через HH API.
- Не путать ошибки доступа с отсутствием вакансии.
- Позволять выбирать аккаунт и резюме.
- Показывать информацию о вакансии перед откликом.
- Генерировать сопроводительное письмо.
- Позволять отправлять отклик без AI.
- Предотвращать повторные отклики.
- Обрабатывать анкеты и обязательные вопросы в пределах возможностей API.
- Показывать точный результат отправки.

## 5. Ошибки HH API и CAPTCHA

- Раздельно обрабатывать HTTP 400, 401, 403, 404, 429 и 5xx.
- Различать ошибки авторизации, ограничения доступа, CAPTCHA и отсутствие вакансии.
- Использовать штатный механизм CAPTCHA из версии 2.5.4.
- Проверять конфигурацию AI-провайдера, используемого для CAPTCHA.
- Предусмотреть ручное прохождение CAPTCHA, когда это поддерживается.
- Не запускать бесконечные повторные попытки.
- Применять ограниченные повторы с задержками для временных ошибок.
- Приостанавливать отклики при ограничениях HH.
- Отправлять уведомление в Telegram с причиной остановки.
- Корректно возобновлять обработку после устранения проблемы.

## Критерии завершения проекта

Проект можно считать законченным, когда:

1. Все предусмотренные функции доступны через Telegram или документированный CLI.
2. Ручные и автоматические отклики корректно работают с HH Applicant Tool 2.5.4.
3. Ошибки API и CAPTCHA обрабатываются предсказуемо, без ложных сообщений.
4. Все автоматизированные тесты проходят, Docker-сборка успешна.
5. Исходники опубликованы в GitHub, CI работает, документация соответствует коду.
6. Нет известных критических ошибок, препятствующих основным сценариям использования.
